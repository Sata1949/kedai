## ALGO-7 聊天历史：一次投影，按位置借用前缀

- **目标**：加快长会话打开、切换和重载，不删历史、不改变任何单条消息的显示结果。
- **修复前证据**：[API 历史渲染](../../server-rs/src/api/sessions.rs) 的 `history` 在第 `i` 条消息里
  把 `messages[..i]` 全量克隆成 `Vec<(String, String)>`。即使正文没有宏，也会构造前缀。
  3,000 条时共复制 4,498,500 个历史条目，单算正文约 4.6 GB 累计拷贝量，并非峰值内存。
  [会话读取](../../server-rs/src/services/session_service.rs) 已按 `(session_id, id)` 索引取历史；
  加索引不能消除这个复制。
- **改动点**：
  1. 只在该 API 渲染路径中构建一次原始 `(role, content)` 元组，循环内给 `MacroCtx.history` 传
     `&history[..i]`。不引入第二套宏，也不改引擎使用的历史上下文。
  2. 保持同一个显示态变量副本和作用域树按原顺序传递；前缀是**原文**而非已展开的
     `content_display`，不包含当前项，显示态写变量不落库。
  3. 此次线性化只指前缀投影；`last_by_role` 在角色稀疏时仍可反向扫描。若优化后它成为热点，
     再评估每个位置记录最近的 user/assistant 下标，不在本批扩大 `MacroCtx` 契约。
- **验收断言**：
  - 在现有会话 API 集成测试中对拍 `content`、`content_display`、消息顺序与字段；覆盖空会话、首条、
    user/assistant/system 混排、角色不存在、首末条宏、连续 `setvar` / `addvar` 及中文。
    确定性样例逐字节相等；动态时间和随机宏仍在请求内重新展开，不能缓存展开结果。
  - 在可计数的局部探针确认历史投影数从 `N(N-1)/2` 降到 `N`，不把耗时做成单测硬门槛。
    同机同样本 release 对比，**拟议门槛**为 3,000 条 HTTP p95 较重建后的旧基线降低至少 70%，
    300 条不回退超过 `max(5 ms, 旧值的 10%)`，并发 4 个请求时无错误或异常内存增长。
  - 实测若仍主要耗在大响应序列化或传输，另立游标分页计划。分页须先设计前缀宏和变量回放的
    状态恢复，不能仅加 `LIMIT` 就让老消息改变后续显示。
- **实测证据**：128 条 × 1 KiB 的 API 渲染累计申请从 10,705,685 B 降至 2,077,845 B，旧实现被分配回归拒绝；会话 API 专项全绿。真实模型生成、重开会话、原文/显示分离与动态时间宏回归通过；三轮正式 HTTP A/B 响应逐字节一致，3,000 条 p95 每轮下降超过 92%，并发 4 无错误；全量门禁及同步主干后的复跑均通过。详见 [ALGO-7 变更史](../功能-变更史/05-2026-11-01起.md#2026-11-08-algo-7)。仓外证据包 `<bench-root>/algo7-history-evidence-20261107/`。
- **风险 / 回滚**：一次请求会保留一份线性大小的元组，须记录峰值内存；回滚单个渲染补丁即可，
  不需要迁移数据。
- **依赖 / 需确认**：无前端、数据库或上游配置依赖。
- **状态**：已完成（2026-11-08）。**来源**：本次热点实测。

## ALGO-8 工作区搜索：让命中上限真正停止遍历

- **目标**：有足量早期命中时不再扫描后续目录，降低大型工作区的单次搜索延迟和文件系统调用量。
- **修复前证据**：[`run_grep`](../../server-rs/src/tools/agent_tools_fs.rs) 的 `truncated` 只让
  回调返回；[`walk_children`](../../server-rs/src/tools/workspace_scan.rs) 仍枚举、排序、
  递归并对后续条目做 `symlink_metadata`。对进入内容扫描的普通文件，grep 又请求一次 `metadata`。
- **改动点**：
  1. 在现有共享遍历内增加可向根层传播的停止结果（例如 `ControlFlow`）。grep 在确认第
     `max+1` 个命中时立即停止；恰好只有 `max` 个仍应返回确定的命中数。
  2. 把遍历已经取得的普通文件元数据传给 grep 的大小判断。保留同一套排除目录、
     工作区路径闸门、不跟随符号链接与目录内排序，禁止通过新增遍历实现绕开。
  3. 停止原因与 bash 前后扫描的时间、条目预算耗尽分开；`fs_glob` 要给出确定总数，
     不套 grep 的提前结束。无匹配仍需遍历全树，进入的目录仍须按原规则读取并排序子项，
     因此不承诺平坦目录上的常数耗时。
  4. 若修复后「无匹配/窄命中」仍占用 Tokio 工作线程，另测有界阻塞执行与协作取消；
     不把 `spawn_blocking` 的等待超时当成已经终止扫描。
- **验收断言**：覆盖零命中、恰好 `max`、`max+1`、非法正则、glob 路径过滤、二进制与超限文件、
  不可读目录、排除目录和符号链接。对拍前 `max` 条内容、次序、行号、跳过计数及截断文案；
  用测试内计数证明尾部目录不再进入，且原有 bash 扫描的 `Complete/Truncated/Failed` 判据不变。
  **拟议门槛**：5,000 文件首命中样本 p50 至少降低 80%，无命中样本不明显回退。
- **实测证据**：访问条目 25→2，变异被拒绝；全量后端测试与真实模型工具调用通过。5,000 文件早命中三组 p50 为 149.704–154.100 ms→0.293–0.344 ms，无命中无回退，输出一致；四 worker 混合负载无错误。详见 [ALGO-8 变更史](../功能-变更史/05-2026-11-01起.md#2026-11-08-algo-8)，仓外证据包 `<bench-root>/algo8-9-evidence-20261108/`。
- **风险 / 回滚**：共享遍历若错误传播提前停止，会漏文件或把不完整扫描当成完整。保留默认继续语义，
  只让 grep 使用中止分支；可单独回滚该批。
- **依赖 / 需确认**：和 ALGO-7 无代码依赖；只复用已有遍历模块。
- **状态**：已完成（2026-11-08）；同步 I/O 与无命中全树遍历仍为已声明边界。**来源**：本次热点实测。

## ALGO-9 任务详情：在一次请求内复用交付文件检查

- **目标**：减少任务详情刷新对工作区的重复系统调用；下一次请求仍反映外部文件变化。
- **现状证据**：[`GET /api/tasks/{id}`](../../server-rs/src/api/tasks.rs) 读时合成交付摘要。
  [`summarize`](../../server-rs/src/services/task_engine/delivery.rs) 分别为 `missing_files`、
  `content_issues`、文本大小限制和 `files[].exists` 检查同一路径。单文件 HTML 还可能在
  [静态接线](../../server-rs/src/services/task_engine/wiring.rs) 与
  [ESM 边界](../../server-rs/src/services/task_engine/esm_boundary.rs) 中重复读。
  [任务 store](../../web/src/stores/task.ts) 已合并并发中的详情请求，但使用量和 Agent 状态仍会触发新的读取。
- **改动点**：
  1. 摘要内按归一化后的声明路径收集一次文件事实：缺失、非文件、长度、元数据读取失败。
     用同一事实生成 `missing`、`exists`、空文件问题；按既有扩展名和字节上限懒读正文。
  2. 先合并普通声明文件的重复检查。单文件 HTML 如果有重复读，再让各规则消费同一次读取，
     但保留各自的上限、失败回退、结果顺序、去重和截断。根目录卫生扫描与入口回退只有在实测收益
     明确、错误与链接处理等价时才合并；目录很大而只声明少量文件时，不用整目录枚举替代定点查询。
  3. 不缓存整份详情，不仅靠 mtime 判定安全，不把展示缓存用在终态交付门槛上。
- **验收断言**：对拍 `missing`、`files[].exists`、占位符、空白、未声明草稿和单文件静态检查；
  覆盖缺失、目录、不可读、空、非文本、超过大小限制及嵌套路径。两次请求之间删除或改写文件，
  第二次必须立即反映变化。先用计数证明确实减少重复 `metadata` / 正文读取；**拟议门槛**为
  300 文件样本 p95 降低至少 20%，0 / 20 文件样本无明显回退。
- **实测证据**：0~300 文件的详情基线见上；分段耗时、优化后 A/B 和真实任务验收待做。
- **风险 / 回滚**：注意 `DirEntry::metadata` 与按路径读取的符号链接语义不完全相同，不可直接互换；
  保持既有权限和错误口径。请求内数据不落库，可回滚该批恢复原检查。
- **依赖 / 需确认**：承接 ALGO-6-b；首轮不动工作区画像、文件变更台账 SQL、终态自检或前端刷新频率。
- **状态**：未启动。**来源**：本次热点实测与 ALGO-6-b 的待测边界。

## ALGO-10 全局用量：规模达标后才做事务内增量汇总

- **目标 / 现状证据**：[`all_usage_total`](../../server-rs/src/services/task_service/mod.rs)
  每次扫 `task_usage` 做三项 `SUM`，复杂度随保留行数增长；10 万行热态 p95 仅 8.28 ms。
  先记录明细行数、端点频率、DB 执行与读池排队；代表性库反复出现 **p95 ≥ 20 ms**，
  或证实全表求和导致明显读池排队时再启动。
- **改动点**：保留明细作为真值。盘点追加、任务删除级联、导入/合库和迁移入口后，才评估单行物化汇总：
  明细与计数同事务增减；旧库幂等回填；提供与原 `SUM` 核对和可重建路径。不先维护多层汇总，
  不以会陈旧的进程内 TTL 缓存替代精确结果。
- **验收断言**：空库、追加、失败回滚、级联删除、重启、升级和导入后始终与原 `SUM` 一致；
  在 10 万 / 100 万行及并发读写下比较读 p95 和写事务耗时，新增写开销不得抵消收益。
- **实测证据**：现有 SQL 计划和规模曲线见上；触发条件、写代价、迁移对拍和真实任务回归待测。
- **风险 / 回滚**：主要风险是汇总漂移与迁移兼容。保留回退原 `SUM` 的读路径，不依赖清库或降级旧 exe。
- **依赖 / 需确认**：启用前须复核 SQLite schema / migration 契约与级联、导入路径。
- **状态**：未启动，按触发条件评估。**来源**：本次热点实测。

## ALGO-11 工具轮次：证实锁或计数瓶颈后再做增量记账

- **目标 / 现状证据**：[`trim_round_history`](../../server-rs/src/agents/engine/executor/generation.rs)
  每轮持引擎的 token 服务互斥锁做裁剪；[`count_tokens`](../../server-rs/src/services/token_service.rs)
  缓存命中前仍需哈希全文。ALGO-3 已消除同轮裁剪后的反复全量计数；这里要验证的是**跨轮**
  不变前缀的重复计数。先按模型、上下文大小与并行度分别量计数耗时、锁等待和本地请求组装；
  代表性长任务中计数加锁等待持续占本地轮前开销至少 10%，且量级足以影响尾延迟，才开始实现。
- **改动点**：按一次运行维护消息成本和总量，只在追加、删改、摘要或清空工具参数时更新受影响项；
  当计数模型/编码变化或无法证明缓存有效时全量重建。不再为判断缓存有效而逐轮哈希全部消息。
  继续复用 `count_single_message_tokens`，保留正文、思考、工具名与入参和结构开销的原口径。
- **验收断言**：追加、裁剪、压缩、同轮重试、模型切换和取消路径中，增量总量始终等于全量计数；
  对拍裁剪后的消息、工具调用配对和模型出站请求。分别比较单任务与并发任务的本地轮前 p95、锁等待、
  token 用量和真实模型首个可见增量，不能用模型波动冒充本地算法收益。
- **实测证据**：单线程热缓存基线见上；并发锁等待、代表性轮次成本与真实模型结果待测。
- **风险 / 回滚**：失效遗漏会造成预算计数与实际发送不一致。保留全量计数作为对拍基准和回退路径，
  不改裁剪阈值、轮次守卫或分词器。
- **依赖 / 需确认**：须先拿到分段计时，不记录模型正文、工具参数或 API Key。
- **状态**：未启动，按触发条件评估。**来源**：本次热点实测与 ALGO-3 的跨轮边界。

## 公共复测与收口

1. **重建基线。** 同一台机器、同一编译档、同一组隔离夹具分别构建旧版和改版 release。用
   `DATA_DIR`、`LOG_DIR`、`PORT` 启动独立实例，**确认日志中的 `data_dir` 再写入夹具**；
   只访问回环地址，确认完成后停止对应隔离进程。测量时避免并行编译，记录版本、并发、
   预热、样本数、p50/p95、响应字节、错误和重复读写次数。
2. **夹具可重建。** 历史 300 / 1,000 / 3,000 条，交替 user/assistant，编号加固定填充至 1,024 B；
   另加小规模真实宏语义样本。grep 用首文件两行相同关键词、剩余文件分布在后续目录，补无命中与
   `max` 边界。详情用同一目录的 300 个约 1 KB 文本，分别声明 0 / 20 / 100 / 300 个，
   每步最多声明 20 个。用量合成 200 个任务，分批追加固定计数明细。所有样本均不得来自真实用户数据。
3. **性能与正确性分开验收。** 本地探针用来隔离成本，不作为真实模型通过证明。
   同条件 A/B 至少复跑三轮，先对拍输出和访问计数再看耗时；单并发与并发 4 分开记录。
   动核心行为先写能失败的回归，再实现。后端变更跑
   `cargo test --manifest-path server-rs/Cargo.toml -j 8`（加载 MSVC 环境），并按仓库门禁执行。
