## 彩窗主题美观优化（GLASS-A1~A4 / B1~B5 / C1~C3 / D1~D3，2026-11-02 新登记；A+B 已实施，**C1/D 未做**）

- **目标**：解决「彩窗主题（`stained-glass`）看着丑、且很像默认纸面主题」的问题。
  用户判定 + 实测均成立：当前主题把「彩色玻璃拼片」当作**主材质铺满 chrome**，
  导致整屏浅色（亮部 **70.7%**、暗部仅 **4.9%**），与真实彩窗「暗石框里一扇发光玻璃」
  （参照实测：暗部 **29.9~84.1%**、亮部 **4.1~40%**）正好相反——因此读作「印着菱形花纹的纸」。
- **来源**：`docs/plans/GLASS-AESTHETIC-PLAN-2026-11-02.md`（本批执行稿，含六轮试改实测）。
- **根因（量化）**：
  - **结构错位**：真实彩窗层级是「石构(暗) → 乳白玻璃(亮) → 窄彩边(点缀)」；
    现在 Kedai 是「整屏浅色 + 彩色拼片做主材质」，缺暗场、缺焦点。
  - **「拼接」不可感知**：`--kg-mosaic` 是 **384×176 可平铺瓦片**（300 polygon / 23 色 / 菱形固定
    48×44），1440×900 下重复约 **6.9 次**；真实拼片不规则、大小悬殊、紧密咬合、从不重复。
  - **玻璃语义反了**：真实玻璃是**透射自发光**（亮、通透、中低饱和）；现主题是**反射颜料**
    （暗、实、高饱和，顶栏饰带 S=0.607）。
- **A 批（低风险，可独立提交）**：A1 chrome 去密拼片改单色钴蓝玻璃 + 1px 金线；
  A2 面板不透明化（`rgba(...,0.58)` → `#f3eee0`，停止「透出壁纸」）；
  A3 玫瑰窗 140→108px、`opacity .72`、去大范围 glow；
  A4 移动端不透明度回调（`sidebar .88→.80`、`main .74→.68`，低档维持）。
- **B 批（核心）**：B1 废弃可平铺 `--kg-mosaic`，改「按面板尺寸不平铺」的拼片层（大尺寸 SVG 铺满即止，
  或 CSS 多层构造）；B2 彩色只出现在面板**边缘** 6~10px 彩带，彩色面积目标 **≤15%**；
  B3 建立「窗棂」语义（面板间间隙读作石制竖梃 + 内侧 1 条极淡竖线）；
  B4 玻璃**透射发光**语义（顶部向下衰减高光、底部收暗，去掉正面白高光）；
  B5 铅条粗细分层（主窗棂 2px / 拼片缝 1px，允许不均匀）。
- **C 批（缺陷）**：C1 `data-perf-tier` 首帧定死永不重算（本次实测 16 核/8GB/1440×900 被判 `low`，
  仅因首帧视口 1280）；C2 暗底前景色语义缺失（`--sv-white` 同时承担「白底」与「黑底白字」两义，
  `builtin.ts:13` 已注明——**任何暗场改动前必须先补 `--sv-on-dark` 类语义变量**，否则必翻车）；
  C3 移动端主题被不透明度吃掉（拼片透不上来，只剩顶栏一条彩带）。
- **D 批（可选）**：D1 玫瑰窗改空态专属、进对话后淡出；D2 玻璃噪点/厚度不均（`feTurbulence`）；
  D3 暗场下细宋体复核（若 B 批引入局部暗场）。
- **总方针（重要）**：**不做全局 token 反转、不追求整屏暗场**。改为**局部暗场**——暗只发生在
  窗的四周与窗棂上，正文仍落在发光的白玻璃上。依据：试改 A/C/E 三轮实测证明，凡压暗背景，
  组件前景色约定即被成片打穿（`sv-auth-mode-label` 前景 `rgb(51,42,49)` 落在
  `rgba(14,12,20,0.94)` 上，对比度 **1.3:1 = 不可见**）；补全局 `* { color }` 又会把白底按钮
  文字打飞（实测 7 项掉到 **1.28:1**）。逐组件覆盖成本不可控，故不走该路。
- **验收断言**（须实测，不接受「看起来好了」）：
  - 显色量化（1440×900 全屏）：**暗部 ≥25%、亮部 ≤45%、亮度动态范围(p99−p10) ≥0.80**；
  - 可读性：全量扫描可见文本节点，**对比度 <3:1 的项必须为 0**（含暗底与白底两种情形）；
  - 移动端 390×844：面板不透明度 `.80` 以内仍可辨认拼片（不依赖顶栏单条彩带识别主题）；
  - 性能：主题 CSS gzip **≤12KB**（现基线 7.71KB）、切主题 longtask 保持 `[]`。
- **实测证据**：`D:/kedai-bench-run/glass-aesthetic-evidence/`（隔离实例 3021 + IAB 真实浏览器；
  `shots/` 14 张产品截图含六轮试改与移动端，`refs/` 6 张真实彩窗参照照片，`compare-final.png` 对照拼图）。
- **风险 / 回滚**：A 批为纯 CSS 声明、可读性零风险，回滚即恢复对应声明；B 批改的是
  `--kg-mosaic` 生成方式与面板材质层级，需按 B2→B4→B3→B1→B5 逐条出图验收，每条可单独回滚；
  C1 涉及 `main.ts` 判定逻辑（含单测），注意档位重算只在「升级到 high」时触发，避免主题重绘抖动。
- **状态**：**已实施（2026-11-02，A+B 两批合并交付；C1 未做）**——按用户追加要求
  「第一眼惊艳 + 长期观察不刺眼」重做为 **「石室与光」** 设计模型，实现见下节「落地记录」。
  C1（`perf-tier` 重算）不在本批，仍待办。
- **来源**：`docs/plans/GLASS-AESTHETIC-PLAN-2026-11-02.md`（执行稿，保留供复查）。

### 落地记录（2026-11-02，单文件 `web/src/theme/stained-glass.css` 全量重写）

- **设计模型**（对应真实彩窗的物理结构，三层）：
  - **层 0 石室**：`#0b0910` 近黑微暖 + 三束极淡彩光 + 四角暗角（`radial-gradient` 压到 42%→100%）。
  - **层 1 窗**：面板 = **一整块从背后发光的玻璃**。主窗 `#ece5d6`（暖象牙，不是纯白）、
    侧窗 `#ddd5c2`（暗一档，建立主次）。玻璃感由**厚度**承担：4 层描边模拟石框
    （`0 0 0 1px/2px/4px/5px`）+ `inset 0 2px 0` 上缘聚光 + `inset 0 0 52px` 内缘暗边 +
    `0 0 160px` 外辉光。窗楣 3px 窄彩带、窗台 1px 金线收底。
  - **层 2 石梁/窗台**：顶栏与输入区近黑 `#08060f`，只留一条暖金边（被窗光照到）。
- **彩色玻璃降级为「稀缺资源」**：全站只留三处——窗楣窄带、选中态（模式拨杆/角色卡）、
  主按钮；其余 chrome 一律素玻璃。**`--kg-mosaic`（384×176 / 300 polygon / 23 色 / 每屏重复
  6.9 次）整条删除**，11 处引用全部移除；`--kg-rose` 保留（空态玫瑰窗仍用）。
- **排版是「惊艳」的真正来源**（这批的最大发现）：空态标题原先**用 Cinzel 渲染中文**
  （无中文字形 → 掉回宋体且 `letter-spacing: -0.38px`），且内容区只占画布左侧 347~385px、
  右侧大片空洞。改为：中文族 `Noto Serif SC` + `clamp(30px,3.1vw,42px)` + `line-height 1.28`
  + `letter-spacing 0.02em`；两栏 `1.45fr / 1fr` + `gap 72px` + 右栏竖向石棂，消除空洞。
- **长时间工作的三个护眼约束**：① 玻璃用暖象牙而非纯白；② 正文宋体 + `line-height 1.92`
  （实测 42 字/行，落在中文长读舒适区）；③ 全站对比度 ≥3:1（实测 **0 项**不达标）。
- **实测验收（真实构建产物，1440×900 / 390×844）**：
  - **眩光风险（亮度>0.94 且 饱和度<0.06 的面积占比）：12.5% → 0.3%（空态）/ 0.0%（任务）/ 0.0%（移动端）**；
  - 过亮区 66.5% → 46.7% / 38.0% / 48.4%；暗部 7.7% → 17.2% / 14.2% / 17.4%；
  - 亮度动态范围 0.919 → **0.963 / 0.963 / 0.967**（真实彩窗参照为 0.87~0.98）；
  - 对比度扫描：空态 0 项、消息页 0 项、设置页 0 项、任务页 0 项 <3:1；
  - 主题 CSS **29.5KB raw / 5.58KB gzip**（原 7.71KB，**降 28%**，因删掉 300 polygon 的拼片 SVG）；
  - 前端测试 **174 文件 / 1865 用例全绿**；`check-arch` / `check-css-discipline` /
    `check-docs` / `check-doc-claims` / `count-tests --check` 全 OK。
- **过程中修复的三个真实缺陷**（均由本次实测抓出，非计划内）：
  - **移动端布局崩塌**：主题块里无条件写 `.sv-sidebar { position: relative }`（带 `html[data-theme]`
    前缀，特异性高于 `mobile.css` 的 `.sv-sidebar`），把 `position: fixed` 的覆盖式抽屉拽回文档流，
    占掉 320px → 主区被挤到 **55px 宽**、正文竖向断字。修法：`position` 只在
    `@media (min-width: 768px)` 内声明。修后主区恢复 **390px 全宽**。
  - **禁用态主按钮不可读**：任务模式「创建并执行」在 disabled 时背景与文字同为灰调，
    实测 **1.41:1**；补显式禁用配色后 **5.52:1**。
  - **顶栏/侧栏头深色文字压暗底（6 处）**：顶栏从「半透明深蓝」改「近黑石梁」后，
    token 卡片数字与开关标签仍是深色，实测 **1.2 / 2.94 / 2.09:1**；
    旧版那条 `.sv-side-head .sv-sidebar-close { color: #f5ecd9 }` 重写时漏掉，
    移动端抽屉关闭键落到 **1.15:1**（实际修饰后 **16.5:1**）。补齐「暗石梁内一律暖白」整组规则后归零。
- **证据**：`D:/kedai-bench-run/glass-aesthetic-evidence/`（`final-design.css` 最终稿、
  `stained-glass.css.bak` 旧版备份、`shots/` 含 10 轮迭代与最终四界面 + 移动端、`refs/` 6 张
  真实彩窗参照、`compare-DESIGN-FINAL.png` 前后对照）。
- **未做（仍开放）**：`GLASS-C1`（`perf-tier` 首帧定死不复算，本次实测 16 核/8GB/1440×900
  因首帧 1280 被判 `low`）；`GLASS-D1~D3`（玫瑰窗空态专属/玻璃噪点/暗场宋体复核）；
  大面板实时 `backdrop-filter` 与 Windows 亚克力沿用 `遗留.md` GLASS1-L1/L2 的「知情不做」。

### 落地记录之二：拼接玻璃（GLASS-PANE-1，2026-11-02 同日晚）

> 上一轮「石室与光」解决了「丑」，但同时把「拼接」这个核心视觉**整条删掉了**——
> 实测全界面 `pattern: false` 100%，没有任何多块玻璃结构。本批把它补回来，
> 并且是按**真实彩窗的构造语法**补，不是把旧壁纸搬回来。

- **纹理：从「随机多边形」改成「石棂 + 菱形小片」**
  - 第一版重生成了 48 块完全随机的多边形，实测读作**碎玻璃／迷彩**——缺的不是
    「不规则」，而是**规整的骨架**。
  - 参照本地真实彩窗照片（`glass-aesthetic-evidence/refs/`：Cologne Richter 窗、
    哥特长窗、拱窗）得出的构造语法：**大尺度是刚性石棂**（等距竖棂 lancet + 横档
    saddle bar + 上下窗框），**小尺度才是玻璃片**（格内错缝咬合的菱形 quarry）。
  - 最终产物是 `--kg-panes-band`：560×80 的横向条带，一个周期含 2 个光窗 + 2 条竖棂，
    `background-repeat: repeat-x` 自适应平铺。**不再用竖窗大图做极端缩放取样**——
    顶栏只有 68px 高，取到的永远是某块局部，比例与亮度都不对。
  - 菱形咬合的关键几何：行距 = **半高**（不是全高）。写成全高时菱形只在顶点相碰、
    中间露出大片暗格，读作「菱格纹地砖」（实测过一轮）。
- **染色：用 `background-blend-mode: multiply`，不是盖暗罩**
  - 拼片是「浅象牙底 + 近黑铅条」，直接铺在近黑石梁上读作灰白纸片；盖暗罩只会压成
    一片均匀的灰。与深钴蓝（`#4a68a8`）相乘后，浅底变成**透光的暗蓝玻璃**、铅条仍是黑。
  - 实测三档对照：纯 0.50 暗罩 = 灰白纸片无彩色 / multiply + `#1d3a70` = 玻璃发乌 /
    multiply + `#4a68a8` = **暗蓝透光、铅条清晰**。
- **透明感与光泽：靠分层叠加，不靠加白**
  - 玻璃片 `fill-opacity` 0.6~0.7，让底下的石室色透上来（"透"的来源）；
  - 每片内部有沿斜边的高光 + 右下暗部（厚度反光）；
  - 条带内嵌两条贯穿式斜向反光（窗面整体镜面反射）；
  - CSS 再补顶部天光、`inset` 顶/底 1px 亮边、底部内阴影。
- **分层边界（本批最关键的约束）**：拼片只允许出现在**装饰层**（顶栏窗楣）与
  **强调层**（角色卡选中态、主按钮，必须先 multiply 染色）。**内容层**
  （主面板/侧栏/消息气泡/输入框/模态/hub）一律素玻璃——只要拼片是背景，文字就必然
  跨越铅条。这条由 `stainedGlassCss.test.ts` 机检（白名单制，新增用点要显式登记）。
- **第 ⑦ 轮遗留的解法**：顶栏铺拼片后 AGENT/CTX/本轮 被衬糊。做法是给每个控件组
  垫一层 `rgba(9,14,32,0.72)` 近黑玻璃 + 内侧金边，让它们「从拼片里浮起来」；
  比提高整条覆盖层浓度更好（后者会把彩色感一起抹掉）。
- **空态装饰：用户裁定「装饰条太丑」，已撤掉**
  - 中途试过右栏拼片横带、两栏竖棂、底部窗槛，均被否；最终**不留任何装饰条**。
  - 留白改由**版式本身**解决：两栏撑满可用高度，左栏在「说明簇 / 步骤表 / 模式+按钮」
    之间按阅读节奏分散（`margin-top: auto` 只作用于模式行），不整块 `space-between`
    ——那会把标题与描述之间撑出上百像素的缝。
- **顺带修掉的真实缺陷（4 类）**：
  - **空态网格整个空转**：`grid-template-columns` 与 `gap` 写在 `.sv-start` 上，
    而真正的 grid 容器是 `.sv-start-grid` / `.sv-task-start-grid`——**4 处声明从未生效**。
  - **顶栏统计区 1.15:1**：`.sv-topbar *` 把文字刷成暖白，但统计格与窄屏溢出菜单底仍是
    `--sv-white`。改为暗玻璃内嵌格并逐项翻暖白。
  - **提示条 1.87:1 / 关闭键 1.16:1**：`.sv-render-hint` 是「浅蓝底 + 深蓝字」，落到
    近黑石室上只剩 1.87；其关闭键还是白底配暖白字 1.16。改暗玻璃 + 透明暗底。
  - **死选择器与死令牌**：`.sv-topbar .sv-token-cell`（该类只在侧栏头）删除；
    `--kg-lead-soft` / `--kg-sapphire-lit` / `--kg-emerald` / `--kg-amethyst` 删除
    （`--kg-ruby` 启用为主按钮底色）。
- **实测验收（1440×900 真实构建产物，隔离实例 3077）**：
  - 对比度扫描：聊天空态 **0 项** <3:1（78 个文本节点）/ 任务台 **0 项**（73 个）；
  - 眩光风险 **0.1% / 0.0%**（原 0.3% / 0.0%，未被破坏反而更稳）；
    过亮区 **6.7% / 2.0%**（原 46.7% / 38.0%，顶栏改暗后大幅下降）；
    暗部 **24.6% / 19.9%**；动态范围 **0.928 / 0.916**；
  - 主题 CSS **11,467 gz**（原 5,835，+5,632 来自拼片条带；仍在 12,000 默认预算内）；
  - 前端测试 **175 文件 / 1890 用例全绿**（含新增 8 例契约测试）；
    `check-bundle` / `check-css-discipline` / `count-tests --check` 全 OK。
- **证据**：`D:/kedai-bench-run/glass-pane1-evidence/`
  （`panes-band.svg` / `.uri.txt` 最终纹理源、`shots/v3-{roleplay,task}-1440.png` 最终两模式、
  `shots/final-*` / `deco-*` 含中间尝试与被否方案的对照）。
- **未做（本批不做）**：纹理配色未再做细调（现为冷玻璃场 + 3% 彩斑）；中低端设备拼片
  光栅化的帧耗时未取证；任务台空态没有玫瑰窗那样的焦点，仅有顶栏窗楣呼应。

## 任务模式消息显示三档（TMSHOW-1~TMSHOW-4，2026-11-01 新登记）

- **目标**：把任务模式的「执行过程」显示拆成用户可切换的三档，并补齐支撑档 2 / 档 3 的
  **中间过程数据层**——当前任务模式完全不保存思考正文、工具入参与出参、bash 输出，
  所谓「全消息显示」在做完数据层之前无从谈起。

  | 档 | 内部名 | 呈现 |
  |---|---|---|
  | 一 | `legacy` | 优化后的旧方式：计划步骤时间线精修（状态色带、长结果折叠），不显示中间过程 |
  | 二 | `full` | 扁平全消息时间线：每条思考 / 工具调用 / 工具结果 / 步骤产出独立成条，按 `seq` 排序 |
  | 三 | `condensed` | 按 `phase + step_index` 分组，每组一张 assistant 卡；中间过程折叠其内，右下角显示「思考 N · 工具 N · bash N」 |

- **现状证据**（2026-11-01 代码实测）：
  - 思考正文：`agents/engine/executor/generation.rs::process_chunk` 把 `LlmStreamChunk::Reasoning`
    累进局部 `reasoning` 后**从不外发也从不落库**（聊天侧亦无对应事件）；
    任务侧纯生成旁路 `services/task_service/executor.rs` 只累加 `reasoning_chars`。全仓
    `grep` 无 `SseEvent::Reasoning`、无 `TaskEventKind` 思考类取值。
  - 工具调用：`services/task_engine/sink.rs::map_event` 把 `ToolCall` / `ToolResult` 压成
    单行中文状态（`DETAIL_MAX_CHARS = 200`），**不带入参、不带出参、不带 call_id**。
  - bash 输出：`tools/bash.rs` 的完整输出只回灌模型；`exec_audit` 留 2000 字摘要但
    `GET /api/exec/audit` 的 `AuditQuery` **没有 task_id 过滤参数**，任务侧无法按任务取。
  - 结构化轨迹落库不存在：任务路径 `agent_session=None`（`tool_loop/round.rs`），不写
    `agent_sessions` / `tool_calls`；`task_llm_calls` 只有双截断摘要（每条消息 800 / 整体 4000）。
  - 前端：任务气泡不复用 `ChatMessageItem`，是 `task/TaskResultPanel.vue` 内的手写模板；
    无工具卡、无思考折叠、无虚拟滚动；「正在生成」是纯文本块（`task/TaskExecutionPanel.vue`）。
  - `docs/遗留.md` OBS-1 已登记「工具循环整轮只落一行调用记录」属**知情接受**，
    本批不推翻它（`task_llm_calls` 口径不动），轨迹另立表。

- **风险 / 回滚**：最大风险是**数据体量**——`task_trace` 若不设闸门，单任务可膨胀到几十 MB；
  缓解为写入侧硬截断（思考与工具入参/出参各 8000 字）+ 单任务行数窗口（2000 条，超出按
  `seq` 删最旧，与 `task_events` 同口径）。次要是 `SseEvent` 加变体：前端 `sseReducer` 与
  `stores/task.ts` 的 `never` 穷尽断言会在漏接线时**编译失败**（本批实测两处如期报
  TS2322），这是保护而非风险。回滚路径：默认档改回 `legacy` 即恢复现有观感；表与端点均为
  纯加性，旧前端完全无感。**TMSHOW-3 的风险面是偏好错位**——若把任务级覆盖误写成全局默认，
  用户会「改一个任务却影响了所有任务」；本批用两把独立键 + 一条断言（场景 ① 检查全局键未被写）
  钉住。回滚 = 删两个键即恢复默认档行为。

### 二维批次 7b 对比模式(模型可调用名单内流程)(规模 L,3~10 天)

  工具面与记账口径,blast radius 显著更大;(丙)字面「对比」= 执行器把同一目标跑完名单内全部流程
  再由模型汇总——与原文验收断言(模型可自主调用 / 名单外被拒 / 超预算熔断)不一致。
