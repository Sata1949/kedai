### 两条宿主假象（勿误判为产品缺陷）

1. **rAF 不推进**：本宿主 `requestAnimationFrame` 500ms 内 0 帧，所有 CSS 过渡与 Vue `<Transition>`

## 一、结论先行

**用户的判断是对的，而且原因是可量化的：现在的彩窗主题不是「玻璃」，是「印着菱形花纹的浅色纸」。**

三条量化证据（1440×900 全屏统计）：

| 指标 | 真实彩窗（4 张参照均值） | Kedai 现状 | 判读 |
|---|---|---|---|
| 暗部占比（亮度 <0.25） | **29.9% ~ 84.1%** | **4.9%** | 真实窗有厚重暗石/铅条；Kedai 几乎没有暗 |
| 亮部占比（亮度 >0.75） | 4.1% ~ 40.0% | **70.7%** | Kedai 七成画面是亮的 = 纸面，不是窗 |
| 亮度动态范围（p99−p10） | **0.87 ~ 0.98** | **0.67** | 真实窗「近黑 → 强发光」全域；Kedai 挤在 0.32~0.99 |

一句话：**真实彩窗是「暗场里一小块发光体」，Kedai 是「整屏浅色纸上贴花纹」。**
这就是「同时很像原主题」的根因——原主题（纸面·至上主义）本来就是整屏浅色纸。

### 为什么「拼接」也感觉不到

`--kg-mosaic`（`stained-glass.css:28`）是一张 **384×176 的可平铺瓦片**，内含 **300 个 polygon、23 种颜色**，
菱形固定 **48×44**，在 1440×900 下平铺约 **6.9 次**。真实彩窗的玻璃块是**不规则、大小悬殊、紧密咬合**
（铅条是拼片的边，不是缝隙），而且**从不重复**。用「均质可平铺网格」表达「手工拼接」，视觉上必然读作壁纸。

### 次要但确定的缺陷

- **移动端主题几乎完全消失**：`@media (max-width:767px)` 把面板不透明度从 `.58` 抬到 `.88`，
  再叠低档 `.88`，实测 `sidebar` = `rgba(250,246,232,0.88)`、`main` = `rgba(250,246,232,0.74)`，
  拼片完全透不上来，只剩顶栏一条彩带（证据 `shots/18-mobile-390.png`）。
- **`data-perf-tier` 首帧定死不再重算**：窗口从窄变宽后仍锁在 `low`（本次实测：16 核 / 8GB / 1440×900 被判 `low`）。
- **暗场方案的可读性地雷**：试改 A/C/E 三轮里，凡把背景压暗，都会撞上「组件前景色仍是深色 token」
  （实测 `svg-auth-mode-label` 的 `rgb(51,42,49)` 落在 `rgba(14,12,20,0.94)` 上，对比度约 **1.3:1 = 不可见**）。
  这不是一处两处，而是成片（详见 §三 方案 C 的失败记录）。

## 二、真实彩窗照片的拆分观察

> 参照 7 张真实照片（`refs/ref_*.jpg`，Pexels 开放授权）。以下是对**画面结构**的拆解，不是凭印象。

### 2.1 结构层（最重要的一条）

以 `ref_gothic_church.jpg`（哥特教堂长窗）与 `ref_arched_large.jpg`（拱窗）为例，**从大到小**：

1. **石构（最大面积）**：近黑的墙与窗套，几乎不带任何色彩信息，承担「画面暗部」。
   实测该图暗部 **84.1%**。
2. **窗棂（石制竖梃 + 横档）**：把整窗切成 3~5 个竖长格；**这些是粗的、有厚度的、投下阴影的**。
3. **乳白玻璃主体（第二大面积）**：长窗的绝大部分是无彩的浅色玻璃（`grisaille`），提供「透光」，
   也提供文字若在此处的可读基底。
4. **窄彩色边饰带**：彩色玻璃**只出现在窗的边缘一窄条**（每格侧边约 1~2 个拼片宽度），
   以及顶部的圆花窗。它不是主体，是「镶边」。
5. **铅条**：1~2px、**粗细不均**、随拼片走的不规则折线。

> **推论**：现在 Kedai 把「彩色拼片」当成主材质铺满 chrome，与真实结构正好**相反**。
> 真实的顺序是「石(暗) → 白玻璃(亮) → 窄彩边(点缀)」。

### 2.2 色彩层

以 `ref_cologne_gothic.jpg`（科隆 Richter 窗）为例，可读出与 Kedai 现状的差距：

| 维度 | 真实（科隆窗） | Kedai 现状 |
|---|---|---|
| 主色 | 淡蓝 `#a8c8e8`、粉 `#d4a8b8`、乳白 `#e8dfd9`、浅紫 | 深钴蓝 `#143a7c`、红宝石 `#8e1b33`、金 `#c99a3b`（**深、浓、暗**） |
| 饱和度 | **中等偏低**（大面积是接近无彩的淡色） | 高（顶栏饰带 S=0.607、角色卡 S=0.565） |
| 明度 | 玻璃本身**高亮**（被背后光照亮） | 玻璃块本身是**深色颜料**（被正面照亮） |
| 色数 | 有效色相 4~5 个 | 23 种填充色（菱形网格） |

> **关键认知**：真实彩窗的玻璃是**自发光体**（透射光），Kedai 现在做的是**反光颜料**（反射光）。
> 前者亮、通透、低饱和；后者暗、实、高饱和。这是「像不像玻璃」的分水岭。

### 2.3 光图层

- **发光**：玻璃从背后被点亮，与周围暗石形成 **10:1 以上**的局部对比；边缘有轻微光溢出（bloom）。
- **暗角**：照片四周明显压暗（`ref_brasov_warm.jpg` 暗部 **73.4%**），把视线压到窗上。
- **无均匀纹理**：没有任何一张真实照片存在「等距重复的花纹」。

## 三、试改验证记录（六轮，全部实测）

> 每轮都是「注入 CSS → 截图 → 量测 → 移除」。截图在 `shots/`。

### 方案 A：暗场 + 发光玻璃（`11-variantA-dark.png`）

- **做法**：外壳压到 `#0a0810`，面板改 `rgba(18,16,26,0.80)`，顶栏/输入区同步压暗。
- **正向**：暗部 4.9% → **78.2%**，亮部 70.7% → **7.9%**，**落进真实彩窗的区间**。教堂感立刻出现。
- **致命问题**：**正文大面积不可读**。截图里「模型 / 连接 / 会话 / 输入含算式…」几乎消失。
  实测 `svg-auth-mode-label` 前景 `rgb(51,42,49)` 在 `rgba(14,12,20,0.94)` 上，对比度 **1.3:1**。
- **结论**：方向对，但**改背景必然会打穿一批组件的前景色约定**。这不是补几条规则能收口的。

### 方案 B：乳白玻璃 + 窄彩边（`12-variantB-ecru.png`）

- **做法**：面板提亮到 `0.955`，外壳压黑，面板顶部加 5px 彩带。
- **正向**：可读性零风险，结构上更接近「石框 + 白玻璃 + 彩边」。
- **问题**：量化后暗部 **5.4%**、亮部 **71.5%**，与现状（4.9% / 70.7%）**几乎一致**——
  即「视觉上仍然很像原主题」。顶部彩带读作「贴纸」，因为它是**后加的装饰**而非结构件。
- **结论**：这一步不足以解决问题，但它是**安全的地基**（可读性不倒退）。

### 方案 C：完整 token 反转（`13-variantC-glassfield.png`）

- **做法**：把 `--sv-ink` 系反成浅色、`--sv-paper` 系压暗，一次性反转整套调色板。
- **结果**：**回归严重**。`严格/宽松/放行` 等按钮文字变成深色压在深底上、`主要` 按钮失去对比。
- **根因**：组件库用 `--sv-white` **同时**承担「白底」与「黑底白字」两种语义
  （`builtin.ts:13` 的注释已写明这一点）。反转 token 会让这两个语义同时翻面，必然打架。
- **结论**：**token 反转这条路不可走**。要暗场，只能逐组件精确覆盖，成本极高。

### 方案 D：窗嵌石框（`14-variantD-window.png`）

- **做法**：保留浅色正文层，只把外壳压黑 + 面板加多重石框描边 + 强投影。
- **正向**：可读性零风险；「一扇窗浮在暗室里」的关系成立。
- **问题**：**仍然像原主题**（亮部 71.5%）。因为面板本体的材质没变，只是换了外框。
- **结论**：作为**必选的基础层**（成本最低、风险最低），但不能单独收口。

### 方案 E：石棂窗框（`15-variantE-mullion.png`）

- **做法**：D 的窗框 + 深色输入条 + 玫瑰窗加重描边。
- **正向**：教堂感最强的一张。
- **问题**：**输入条压暗后，工具行文字成片不可见**（`02DEEP / 03AGENT / 04CUSTOM / 快速回复 / 选择文件`）。
  补一条 `* { color }` 全局提亮后（`16-variantE-fixed.png`），**又把白底按钮上的深色文字打飞**
  （实测 7 项对比度掉到 **1.28:1**）。
- **结论**：再次证明「暗底 = 全局规则必然反噬」，只能逐组件覆盖。

### P0：低成本高收益（`17-P0-lowrisk.png`）

- **做法**：保留浅色正文层；四件事——① 面板改**不透明**乳白（不再透拼片）② chrome 去密拼改单色玻璃
  ③ 顶栏 4px 密拼饰带改 1px 金线 ④ 玫瑰窗缩小降饱和。
- **结果**：**干净、可读、零风险**，但那层「纸感」还在——仍是「整屏浅色」。
- **结论**：这是**任何方案的第一批提交**（先去掉最刺眼的三处噪音），但它**不是解**。

## 四、优化计划

### 总方针（重要，避免再走弯路）

**不做全局 token 反转，不追求「整屏暗场」。改成「局部暗场」——暗只发生在窗的四周与窗棂上，
正文仍落在发光的白玻璃上。**

理由有三：
1. 真实彩窗本身就是「暗石 + 亮玻璃」的对比，不是全暗；
2. 全局暗场已被 A/C/E 三轮证明会打穿组件前景色约定（成本不可控）；
3. 局部暗场只需动**外壳与边框**，正文层（`.sv-canvas` 及其内部）**一行不用改**，可读性零风险。

对应到真实照片的层级：**石构/窗棂 = 局部暗场；乳白玻璃 = 不变的正文层；彩色玻璃 = 只出现在边缘与选中态。**

### P0（第一批，低风险，可独立提交）

> 目标：去掉三处最刺眼的噪音，让主题「不那么吵」。可读性零风险。

| 编号 | 改动 | 实测依据 | 涉及文件 |
|---|---|---|---|
| **GLASS-A1** | **chrome 去密拼片**：`.sv-topbar` / `.sv-side-head` / `.sv-modal-head` 的 `repeating-linear-gradient` 彩带与 `--kg-mosaic` 底纹改为**单色钴蓝玻璃 + 1px 金线** | 顶栏饰带实测 98.3% 像素是彩色的、S=0.607，是全界面最吵的一块 | `stained-glass.css:118-216, 375-394` |
| **GLASS-A2** | **面板不透明化**：`.sv-sidebar` / `.sv-main` 从 `rgba(...,0.58)` 改**不透明** `#f3eee0` + 边缘金线，取消「透出拼片」 | 现方案靠透出拼片制造玻璃感，但透出的是**壁纸**，反而强化「纸感」 | `stained-glass.css:55-75` |
| **GLASS-A3** | **玫瑰窗收敛**：从 140px 降到 **~108px**、`opacity .72`、去掉大范围 glow | 实测玫瑰窗区域 S=0.568、彩色占比 79%，在空态里是视觉焦点，抢了正文 | `stained-glass.css:402-425` |
| **GLASS-A4** | **移动端不透明度回调**：`max-width:767px` 下把 `.sv-sidebar` 从 `.88` 降回 `.80`、`.sv-main` 从 `.74` 降回 `.68`（低档维持现有值） | 实测移动端拼片完全透不上来，主题只剩顶栏一条彩带（`18-mobile-390.png`） | `stained-glass.css:603-616, 646-653` |

> A1~A3 已用 P0 试改验证过整体效果（`17-P0-lowrisk.png`），四项可合成一个提交。

### P1（核心，解决「不像拼接玻璃」）

> 目标：让「拼接」这件事**在结构上成立**，而不是靠一张平铺花纹。

| 编号 | 改动 | 依据 |
|---|---|---|
| **GLASS-B1** | **废弃可平铺 `--kg-mosaic`，改为「按面板尺寸生成的、不平铺的」拼片层**：以 CSS `conic-gradient` + 多层 `linear-gradient` 在**单块面板**内构造不规则分区（不做 tile repeat），或改用一张**大尺寸、不可平铺**的 SVG（≥1024×640，铺满即止） | 现瓦片 384×176、菱形固定 48×44、每屏重复 **6.9 次**——这是「壁纸感」的机制来源。真实彩窗的拼片**从不重复**且大小悬殊 |
| **GLASS-B2** | **彩色玻璃只出现在「边缘」**：面板内缘一圈 **6~10px** 的彩色玻璃带（不规则宽度），面板本体保持乳白；彩色总量目标 **≤15%** 面积 | 真实照片：彩色只占窗的边缘窄条 + 顶部圆花窗（`ref_gothic_church.jpg`、`ref_arched_large.jpg`）；Kedai 现状 chrome 彩色占比达 89.6%~98.3% |
| **GLASS-B3** | **建立「窗棂」语义**：`.sv-sidebar` 与 `.sv-main` 之间的间隙读作**石制竖梃**（深色、有厚度、投两侧阴影），而非「两个卡片」；同时在面板内用 **1 条极淡竖线**象征窗棂分隔，位置固定不随内容 | 真实窗的窗棂是结构件（粗、有阴影）；Kedai 现在是「两块浮起卡片」 |
| **GLASS-B4** | **玻璃自发光语义**：面板顶部加一道**向下衰减的高光**（模拟光线从窗顶透入），底部略微收暗；**不做**正面白色高光（那是反光，不是透光） | 真实玻璃是透射发光：亮部在**上**、暗部在**下**；Kedai 现在用 `radial-gradient` 在中心偏上做白高光，读作「反光塑料」 |
| **GLASS-B5** | **铅条粗细分层**：主窗棂 **2px**、拼片缝 **1px**、并允许**不均匀**（用不同 opacity 的两层叠出粗细变化） | 真实铅条 1~2px 且粗细不均；Kedai 现在统一 2.4px，过粗且等宽，读作「描边」 |

> **B1 是这批的关键技术难点**。若「不平铺的大 SVG」方案被否决，退路是
> `background-size: 100% 100%`（拉伸不重复）+ 足够大的 viewBox，避免出现可辨识的重复周期。

| 编号 | 缺陷 | 实测证据 | 建议 |
|---|---|---|---|
| **GLASS-C1** | **`data-perf-tier` 首帧定死、永不重算**，窄窗口启动的桌面会被永久锁在 `low`（低档 = 面板更不透明 + 关模糊 + 20fps） | 本次实测：16 核 / 8GB / 1440×900 被判 `low`，仅因首帧视口是 1280 | 在 `main.ts` 用 `matchMedia('(max-width:767px)')` 的 `change` 监听重算；或把判定改为「启动后 1 次 + resize 合并重算」。**注意**：档位切换要避免引起主题重绘抖动，建议只在「升级到 high」时重算（降级不主动） |

## 五、执行顺序与验收

### 提交切分（建议）

1. **提交 1 = P0（A1~A4）**：纯 CSS，可读性零风险，独立可回滚。验收：`17-P0-lowrisk.png` 同款截图 + 全量对比度扫描无 <3:1 项。
2. **提交 2 = P2-C1**：`perfTier` 重算（含单测）。验收：窄窗启动 → 拉宽 → `data-perf-tier` 变 `high`。
3. **提交 3 = P1（B1~B5）**：核心。按 B2（彩色只占边缘）→ B4（发光语义）→ B3（窗棂）→ B1（拼片）→ B5（铅条）的顺序做，每步都能单独出图验收。
4. **提交 4 = P3（可选）**。

### 验收标准（每条都要实测，不接受「看起来好了」）

- **量化**：1440×900 全屏统计，目标 **暗部 ≥25%、亮部 ≤45%、动态范围 ≥0.80**
  （对照组：真实彩窗 29.9~84.1% 暗 / 4.1~40% 亮 / 0.87~0.98 范围）。
- **可读性**：全量扫描所有可见文本节点，**对比度 <3:1 的项必须为 0**（含暗底与白底两种情形）。
  扫描脚本可用本次的 `effBg + 相对亮度` 实现，需固化成测试。
- **移动端**：390×844 下主题识别不依赖不透明度（拼片在 `.80` 以内仍可辨）。
- **性能**：改动后 `--kg-mosaic` 若换成大 SVG，需复核主题 CSS gzip 体积
  （现基线 **7.71KB**，上限建议 **≤12KB**）与切主题 longtask（现基线 `[]`）。
- **真实模型**：本批纯样式，按 `AGENTS.md` 豁免条款跑一次最小连通冒烟并在提交正文说明。

### 已知边界（本计划不做）

- **不做全局暗场**（token 反转）——三轮实测证明不可控，见 §三 方案 C。
- **不做 Windows 亚克力/桌面透视**（沿用 `遗留.md` GLASS1-L2）。
- **不做大面板实时 `backdrop-filter`**（沿用 `遗留.md` GLASS1-L1，性能已实测否决）。
- **不新建主题机制**：全部在 `stained-glass.css` + `builtin.ts` 令牌内完成，不碰注册表与插件面。

## 六、一句话总结

> 现在的问题是**「把彩色玻璃当壁纸铺满了整屏浅色纸」**；
> 真实彩窗是**「暗石框里一扇发光的乳白玻璃，彩色只镶在边上」**。
> 修法不是调色，是**改结构**：把暗交给外框，把亮交给正文层，把彩色从「主材质」降级为「镶边」。
