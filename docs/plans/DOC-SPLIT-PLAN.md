## 二、必须先解决的硬约束（否则拆完门禁就红）

这不是"注意事项"，是**拆分的前置条件**。这些脚本按固定路径读文档，文件一移就静默失效或直接 FAIL。

### 约束 1：`check-docs.mjs` 的 D2 白名单锁死 `docs/` 根

```js
const ROOT_ALLOW_DIRS = new Set(['docs/fixtures', 'docs/archive', 'docs/plans']);
```

`docs/` 根下只允许九份活文档 + `README.md` + 上述三个目录。**新建 `docs/功能/` 这类子目录会直接 FAIL。**

### 约束 2：D3 要求 `docs/README.md` 索引与 `CLASSIFIED` 双向一致

`CLASSIFIED` 是脚本里**硬编码的九个主路径**。新独立的 `docs/裁定.md` 算"活文档"，必须同步登记进该数组与 `docs/README.md`，否则 D1/D3 直接 FAIL。它按**计划类分册**登记，不新增第七类。

### 约束 3：D4 只校验 `CLASSIFIED` 里的文件

拆出去的新文件**默认不被链接校验**，等于失去保护。`裁定.md` 必须进 `CLASSIFIED`；后续子目录分卷则靠 X-2 的 D4 扩范围补上。

### 约束 4：`check-doc-claims.mjs` 按**精确路径 + 正则字面**抓值

它读的是**固定路径**，用正则匹配特定句式。**一旦目标文档被拆分或句式被改写，计数口径检查会静默漏检或直接 FAIL。**

|---|---:|---|
| `docs/契约.md` | **19** | **绝对不要拆** |
| `docs/契约-协议与配置.md` | 2 | 不要拆 |
| `docs/契约-架构与数据.md` | 3 | 本就不拆 |

| `MAINTENANCE.md` | 若干 | 不拆 |
| `docs/功能-变更史.md` | **1** | 且限定在文末「事实权威与数字溯源」段——**留在门面即可** |

## 三、方案

### 结论先行

推荐 **方案 A（门面 + 子目录 + 门禁脚本同步改造）**，分八批执行（X-0~X-7），每批独立可回滚。

**实测后的修正结论**：真正需要拆文件的只有 **4 份**——`功能-变更史`（5 卷）、`计划`（3 卷）、`经验`（2 卷）、`功能`（2 卷）；此外先把 `计划.md` §九 的 **29 条裁定整章独立为 `docs/裁定.md`**（1 册，纯移动）。`遗留` 并入单卷不拆；契约两份**不拆文件**只做章内下钻。

按行数硬切成 `part1/part2` 不推荐——那是把可读性问题换成导航混乱。

### 方案 A：`docs/<文档名>/` 子目录 + 六类文档降为"索引门面"

结构：

```
docs/
├── 计划.md              ← 门面：抬头体例 + 条目模板 + §九 锚点占位 + 章节索引表
├── 裁定.md              ← 计划类分册：原 §九 全文（29 条裁定，编号 1~29 原样）
├── 计划/
│   ├── 01-批次记录.md
│   ├── 02-批次记录.md
│   └── 03-常设章.md      ← §四~§十（不含 §九 正文，仅保留占位）
├── 功能-变更史.md       ← 门面：抬头 + 220 行沿革索引段
├── 功能-变更史/
│   ├── 01-2026-08-21起.md
│   ├── 02-2026-09-22起.md
│   ├── ...
│   └── 05-2026-11-01起.md
├── 经验.md / 经验/
├── 功能.md / 功能/
├── 遗留.md              ← 不拆，仅章内下钻
└── 契约*.md             ← 不拆，仅章内下钻
```

**为什么用"门面 + 子目录"而不是直接拆成 `计划-1.md`、`计划-2.md`**：

1. `CLASSIFIED` 里的九份主路径**全部保持不变**——`docs/计划.md` 仍存在，只是变薄。这同时保住 D1/D3 与 `check-doc-claims` 里所有按路径读的检查。新增的 `裁定.md` 按**第十份活文档**登记（计划类分册），不是新的文档类。
2. 门面承载：抬头体例、条目模板、**完整章节索引表**（章节名 → 子文件链接）。读者体验与今天一致。
3. 子目录内容不需要登记进 `CLASSIFIED`（它们是"正文分卷"，不是新的一类活文档）。

需要改的门禁：

| 脚本 | 改动 | 风险 |
|---|---|---|
| `check-docs.mjs` | `ROOT_ALLOW_DIRS` 增加 `docs/计划` 等子目录（按实际拆的文档） | 低，白名单加项 |
| `check-docs.mjs` D4 | 把子目录下的 `.md` 也纳入链接校验 | 低，扩范围 |
| `check-doc-claims.mjs` | **逐条复核**：凡 `file:` 指向被拆文档的检查，确认目标句仍留在门面文件里；若被移走，需改路径或把该句**刻意留在门面** | **高**，见 §四 |
| `docs/README.md` | 六类视图表补子目录说明 | 低 |

## 七、把"索引与子文件一致"变成门禁（D8）

拆分引入了新的一致性要求，必须机器守护，否则半年后一定漂移。在 `check-docs.mjs` 加 **D8**：

```
D8 门面索引完整性
  凡 docs/<活文档>/ 子目录存在时：
    正向 —— 门面 <活文档>.md 内必须有指向该子目录下每一个 .md 的链接
    反向 —— 门面索引里不得出现该子目录下不存在的文件
```

这是 D3 在子目录上的自然延伸。**与 X-1 同批实现**，这样拆分过程本身就有保护，不必等到最后才发现索引漏挂。

顺带建议：D4 的链接校验范围从 `CLASSIFIED` 扩到「`CLASSIFIED` ∪ 所有子目录内 `.md`」——否则拆出去的分卷会失去链接保护（这是当前方案里唯一的保护缺口）。
