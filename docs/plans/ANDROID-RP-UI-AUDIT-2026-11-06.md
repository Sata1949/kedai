# 安卓角色扮演移动端观感审计与重排（2026-11-06）

> **读前提示**：本稿是**调查报告**，不是执行计划。开放项若要开工，按 `docs/计划.md`
> 的条目体例另立；判定为「接受不修」的项按 `docs/遗留.md` 的 R1–R6 登记。
>
> **证据边界**：`before` 是模拟器上已安装的 **0.4.5 APK**（旧前端）；`after` 是
> `web/dist` 在 411×914 视口下的真实渲染，并手动把消息操作行设为常显以模拟安卓
> `@media (hover: none)`。**最终 APK 已于 15:34 重建并安装到 emulator-5554**；
> 空态序号与输入框对齐已在真机上复核（截图 `37-android-after-tutorial.png`），
> 用户消息操作行仍只有浏览器 `hover:none` 证据（新装设备数据里没有用户消息）。

## 〇、一句话结论

「丑」不是因为配色或主题，而是**桌面版式被直接塞进 411px** 之后产生的三类结构性失配：

1. **触屏语义失配**：桌面靠 `:hover` 隐藏消息操作行；安卓 `hover: none` 把操作行改成常显后，
   用户消息的**气泡与 4 个按钮并列**抢同一行宽——实测气泡被压到 275px 并左移，4 个两字按钮
   各以 **17.6×94px 竖排**。这是最刺眼的一处，且与「加不加留白」无关。
2. **密度失配**：顶栏 4 个盒子、工具条 7 个盒子、空态三栏表格 + 多条 2px 黑杠；
   只看「有没有内容」不看「谁该是主角」，每屏都在同时喊话。
3. **尺度失配**：2px 黑框、4px 硬阴影、24px 段距是桌面海报尺度；在手机上它们不再是
   「编辑部的力量感」，而是把正文宽度和首屏高度一起吃掉。

第二轮按「**每屏只留一个主表面**」重排：输入卡是唯一的墨线主表面，顶栏/工具条只留发丝线，
选中态才落墨块/粉块；页头从 116px 收到 67px，输入区从 179px 收到 153px，消息区多出 31px。
另修一处肉眼可见的对齐缺陷：发送键中心曾比输入框低 **5.73px**（inline-block 基线缝隙），
现在文本域/发送键/SVG 三者中心同为 627.33。

## 一、观察方法

- **真机基准**：`emulator-5554`，1080×2400 @420dpi → CSS 视口 **411×914**；已装
  `com.kedai.app` versionName 0.4.5 / versionCode 4005。截图见证据目录 `01`~`04`。
- **新前端复核**：隔离实例 `PORT=3022`、`DATA_DIR=D:/kedai-bench-run/data-rp-ui-2`、
  `KEDAI_WEB_DIST=D:/kedai/web/dist`；在 IAB 中设 411×914，读取 DOM 的
  `getBoundingClientRect()` 与 `getComputedStyle()`。
- **触屏模拟**：桌面 IAB 报告 `hover: hover`，`mobile.css` 的 `.sv-msg-actions { opacity: 1 }`
  不生效；复核时把 `.sv-msg-actions` 的 `opacity` 手动置 1。**布局规则本身按宽度生效**，
  所以宽/高、换行与挤压的结论不受此影响。
- **测试数据**：`data-rp-ui-2` 内插入 1 个空会话 + 1 个 4 条消息的会话（合成文本），
  不包含任何真实用户聊天正文。

## 二、丑因清单（按影响排序）

### P0｜用户消息操作行把气泡挤成「左边一窄条，右边四根竖字」

- **现象**：安卓上每条用户消息右侧都挂着一列「复 / 编 / 重 / 删」，气泡被压到 275px
  并从右侧滑到左边；文字仍是黑色气泡，看起来像一块被裁坏的引用块。
- **根因**：`.sv-msg` 是 `display:flex` 行布局，用户消息的 `.sv-msg-bubble` 与
  `.sv-msg-actions` 是**并列子项**（`ChatMessageItem.vue` 模板：气泡与操作行同级）；
  桌面靠 `opacity:0` 让操作行不可见，但仍占位；`mobile.css` 在触摸端把 `opacity` 改为 1，
  于是 4 个按钮开始吃宽度。按钮又只设了 `min-height:44px`、没设横向最小宽，
  被压缩后每个只剩 17.6px 宽，中文逐字竖排。
- **实测（411×914，操作行常显）**：
  - 气泡：`x=10, w=275, h=98`；操作行：`x=293, w=100.26, h=94`；按钮：`17.57×94` ×4。
- **修法**（`web/src/components/ChatMessageItem.vue:604` 起的窄屏 scoped 块）：
  用户消息 `flex-wrap: wrap`；操作行 `flex: 1 1 100%; justify-content: flex-end` 落到下一行；
  按钮 `min-width: 44px; white-space: nowrap`，补齐横向触摸区。
- **修后**：气泡 `x=68, w=319`（86%），操作行整行右对齐，按钮 `44×44` 横排。

### P1｜顶栏、页头、输入区三层都在「画盒子」

- **顶栏**：旧版是「会话下拉 + 新建 + 开场 + ⋯」四个带边框控件并排，57~62px 高；
  两个装饰方块（红 + 蓝）并排，第一眼像两个加载失败的徽标。
- **页头**：有消息时是「角色扮演 kicker / 角色名 18px / 模型·会话·条数」三行竖排，
  实测 **92px + 24px 外边距 = 116px**，占 914px 视口的 12.7%；而顶栏和底导航已经分别
  给出了角色名与模式，页头在重复。
- **输入区**：模式四段、授权三段、模型下拉、两个附件按钮**每一个都套一层边框**，
  形成「7 个盒子叠 2 行」的仪表盘；模型下拉因全局 `.sv-select { height: 40px }`
  比同排的模式/授权高 9px；发送键 36px，只有视觉尺寸达标、不满足 44px 触摸下限。
- **发送键对齐**：`.sv-inputbox` 里的 `textarea` 是 inline-block，行盒底部残留 4~6px
  基线缝隙；绝对定位的发送键按更高的 inputbox 算 `bottom: 4px`，实测中心比文本域低
  **5.73px**（text 621.60 / send 627.33），视觉上箭头总是「往下坠」。
- **修法**：
  - 顶栏：会话下拉/新建/开场全部去框（文字 + 幽灵按钮），蓝方块在手机隐藏，只留红方块品牌记号；
    2px 黑杠 + 4px 粉影收到 1px/2px（`ChatTopbar.vue:460`）。
  - 页头：收掉 kicker，标题 15px、元信息 11px，底部改 1px 发丝线（`ChatWindow.vue:982`）。
  - 输入区：工具条只留一条发丝顶线；模式/授权/模型/附件去边框，选中态才保留墨块/粉块；
    模型下拉显式 `height: 30px`；发送键 44×44 黑底（禁用时退回描边）；文本域改 `display: block`
    消除基线缝隙，发送键 `bottom: 4px` 与文本行盒同心（`ChatInput.vue:559`）。
- **修后数值**：顶栏 57px；页头 51px（+16px 外边距）；输入区 153px；消息区 648px；
  文本域/发送键/SVG 中心均为 627.33。

### P2｜空态是「三栏表格 + 两条黑杠 + 两段说明」

- 旧空态在 `sv-start` 顶部有 2px 黑杠，元信息是「模型 / 连接 / 会话」三栏表格，
  下面是两个小号按钮、一行计算器提示、角色索引、再一行说明；信息全对，但**每块都在同一
  个视觉重量上**，没有主角。
- **修法**（`ChatWindow.vue:982`）：
  - 元信息三栏表格 → 一行 `模型 gpt-4o-mini · 连接 检测中 · 会话 2 个`，高度 56→19px；
  - 两个动作改双列 46px 高，主次由黑白面区分；
  - 空态顶部黑杠删除、角色索引区改 1px 发丝线；
  - 计算器提示与「选择角色后开场白会自动进入对话」在手机隐藏（低频信息，桌面保留）；
  - 空态标题 28px，说明 14px/1.8，页边距 16px。
- **修后**：空态内容 489→430px，首屏更松，角色索引完整可见。

### P2｜「最新」浮钮与分叉数据目录提示条

- **「最新」浮钮**：66×34、2px 边框，固定压在消息右下角，实测遮挡正文约两行；
  触摸高度 34px 也不足 44px。本轮未改，登记为开放项（见 §六）。
- **分叉数据目录提示条**（DB-7）：411px 下为 4 行原始路径 + 大号关闭键，约 104px 高，
  是全页最像调试信息的块。它是可操作信息（路径本身就是判据），本轮**不动其语义**，
  只在截图时关闭；移动端是否折行/折叠需另立条目并同步 DB-7 的验收口径。

### P3｜文案与装饰细节

- 空态说明「左侧可随时切换角色与模式」在手机上不成立（没有左侧栏，只有抽屉）；
  已改为「角色与模式可随时切换」，桌面/手机共用。
- **角色索引序号**：手机不再用海报级 display 数字与「01」前缀，改 12px 正文数字、
  右对齐头像中线；模板的 `padStart(2,'0')` 全局取消，桌面保留 15px display 字号但
  计数也变成「1 / 1」。反馈原话：「序列号改的正常一些」。
- 顶栏蓝方块、底部导航 2px 顶线 + 4px 粉影、消息区滚动条等仍保留。
  前者已隐藏；后两者是既有品牌语言，未在本轮推翻。

## 七、这次重排的设计口径（供后续批次复用）

1. **每屏一个主表面**：输入卡是唯一的 1px 墨线主表面；顶栏/页头/工具条只用发丝线分隔。
2. **选中态才落色块**：模式选中=墨块，授权选中=粉块，其余控件下沉为文本色；不再给每个
   可选项都画边框。
3. **留白是结构**：页边距 16px；段距 16/20/24/32 四档；页头与空态的「说明/提示」能删则删，
   而不是缩小字号硬塞。
4. **标题与正文分工**：标题用 display 字体 28px（空态）/15px（页头），正文 14~15px/1.75~1.8；
   元信息 11~12px，只用颜色降级，不再加框。
5. **触摸口径不被视觉让位**：发送键、消息操作按钮 44px；会话/附件等次级图标保持 32~36px，
   与既有 `mobile.css` 的 44px 规则不冲突（后者仍覆盖 `.sv-btn-sm` / `.sv-msg-action`）。
6. **桌面不受牵连**：所有改动都在窄屏 scoped 块；桌面 masthead、三栏空态、工具条盒子语言原样保留。
